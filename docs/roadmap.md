# AI の道具（汎用の Blender 拡張機能）ロードマップ（改訂版）

Mac mini は **32GB**（ユーザー確認）として、全体を見直しました。前の案は約65の機能でしたが、点検の意見をもとに、段階1を小さくし、まちがった見積もりを直しました。

**前の案からの主な変更**
1. **段階1を小さくした**（約20の機能）。残りは「段階1.5」に回しました。
2. **書き出しは紅魔館の `convert_blend.py` に一本化**します。アプリが実際に使う動き（骨に直接当てる動き）での確認を必須にして、段階1の早い所に置きました。
3. **Jeff の使い方を直した**：Jeff に渡すのはプログラムが作る決まった英語の文だけです。数字の「灰色」は Jeff に判断させません。adapter は v1.3 にそろえてから作ります。
4. **32GB の見積もりを直した**：GPU に使える枠は約21〜24GB です。27B の速さは1秒に約4〜6トークンと見ています。どちらも届いた日に測ります。
5. **アプリの中で計算する物は紅魔館の計画に回した**：口パク・セリフから表情・視線・待機の動き。動画から動き などは「将来の候補」にしました。

作る場所はこれまでどおり、非公開のリポジトリ `UJmumei-cmd/blender-ai-tools` です。コードはクラウドのセッションで書き、本物のモデル・LM Studio・Jeff での確認は Mac mini で行います。この案を計画書にして承認をもらってから始めます。始める時期と v070 の置き場所は、7章で決めてもらいます。

## 1. 全体の形

- **Blender の拡張機能**として作ります（Blender 5.2。画面は日本語で、英語にも切り替えられます）。動くのは「道具の目録」に載った関数だけです。AI に自由なプログラムは実行させません。
- **計算はプログラム**です（numpy・Blender の当たり判定・mmd_tools）。どの機能も、**LLM と Jeff が無くてもボタンだけで動きます**。
- **Jeff は、言葉で説明できる選択だけを受け持ちます**。たとえば服の種類や、どの直し方を先に試すかです。
  - 入力は、プログラムが作る決まった英語の文です。変わらない部分を先に、変わる部分を最後に置き、選択肢の名前は数字だけにしません。Jeff は英語と文字だけに対応しているためです。
  - 測った数字の「灰色」は、プログラムの基準と、過去に「このままでよい」とした記録で決めます。小さいモデルは筋道を立てて考えるのが苦手なので、Jeff には任せません。
  - 骨の名前は、MMD・VRM・Mixamo の辞書で決めます。辞書に無い名前だけを聞きます。
  - Jeff は段階2からつなぎます。段階1は「決まった初めの設定＋ユーザーに聞く」だけで全部動きます。
- **会話と計画は大きい LLM** が受け持ちます（LM Studio の Qwen3.8-27B、MLX 5bit。4bit を予備にします）。日本語の頼みは 27B が読みます。27B は道具と値を JSON の形で選ぶだけで、数字は書き換えられません。報告の数字は、プログラムが決まった文の形に入れます。
- **ほかのモデルでも使えます**。最初に「モデルの登録カード」を作り、骨の名前を共通の名前に対応させます。対象は人型のモデルです。
- **書き出しは1本だけにします**。アプリ用の書き出しは紅魔館の `convert_blend.py` が行い、この道具はそれを呼びます。書き出しが2つあると別々に育ち、「Blender では合格なのにアプリでは違う」が起きるためです。

1回の作業の流れ：

```
頼む（ボタン または チャット）
 → チャットのときだけ：27B が分類を決め、その分類の道具（5〜10個）から計画と値を選ぶ
 → 決まった選択肢の中の細かい選択：初めの設定（段階2から Jeff。自信が低いと 27B → ユーザー）
 → プログラムが「写し」で試す → 測る
 → 前後の数字と画像を見せる → ユーザーが確認 → 新しい版（_v001…）で保存
```

## 2. 段階

「大きさ」は作る手間の比較です（S 小・M 中・L 大・XL 特大）。機能の番号は3章の表と同じです。

### 段階0　始める前（Mac mini が届いた日〜段階1の前）

- 7章の「決めてほしいこと」の1〜5に答えてもらいます。答えによって、段階1の中身が変わります。
- Mac mini で次を測ります。
  - GPU に使える枠：`ioreg -l | grep recommendedMaxWorkingSetSize` で測ります。
  - 27B の速さ：1秒あたりのトークン数と、長い前置きを読み込む時間。
  - LM Studio で、画像の読み取り・道具の呼び出し・JSON の形を決めた返事を同時に使えるか。
  - Jeff：v1.3 が出ているか、MLX でどのくらいの速さか。
  - mmd_tools の版と、VPD を読み込めるか（Blender 5 では効かないことがありました）。
- 道具用の CLAUDE.md の下書きを直します。「クラウドでは Jeff は動かないので、試しの返事に置き換える」と書いてありますが、Jeff は CPU でも動きます（5章）。
- 3体目の確かめ用のモデルを用意します（7章の6）。

### 段階1　最小の補正（プログラムだけ。LLM も Jeff もなし）

v070（服の取り込みと自動補正）を、新しいリポジトリの最初の部品として作る案です（7章の3）。モデルのプロジェクトは、それを使う側になります。

作る順番：
1. **守りの土台**：A8 道具の目録／A15 道具の版と再現性の記録
2. **モデルを知る**：A1 モデルの登録カード／A3 骨の名前の対応（辞書）
3. **測る**：A4 測る道具箱／A5 確かめの動き（アプリの動きを含む）
4. **書き出しの基準を作る**：E1 書き出し（`convert_blend.py` を呼ぶ）／E2 往復の確認／E4 アプリの動きで壊れないかの確認
   → ここで、基準用のモデルを書き出して「基準」として保存します。このあとの補正が iPhone で何かを壊していないかを、この基準と比べます。
5. **見せる・戻す**：A6 版の管理と変更点の一覧／A10 裏で動かす係／A11 信号の報告画面
6. **服**：B4 ウェイトの穴埋め転写／B5 服の自動補正（v070 の中心）／B6 衣装ごとの点検
7. **動き**：M1 読み込みと体格合わせ／M4 足の接地／M6 揺れ物の焼き込み

ぶつかる・届かないは、この段階では**見つけて一覧にするまで**にします。自動で直すのは M5 で、段階1.5 です。

**自動で行うこと**：測る、点検、報告、写しでの試し、安全な直し（重なった点をまとめる、面の向き、ウェイトを合計1にして1点4本までにする）。

**ユーザーが確認すること**：部品を消すとき、形が変わる直し、新しい版の適用、アプリのフォルダの置き換え、服の種類（一覧から選ぶ）。辞書に無い骨の名前。

**できあがりの基準（測れる形）**

確かめに使うモデルは3体です。基準用モデル、成人用素体、3体目の人型です。

1. **測る道具の自己テスト**：わざと壊した見本（約20種）を全部見つける。壊していない見本では赤が0。同じ入力を2回測ると、決めた幅の中で同じ数字になる。
2. **確かめの動き**（約40のポーズ、アプリの動き、VMD 3本）：
   - ポーズとアプリの動きでは、アプリのカメラから見える赤の出来事が0。
   - ダンスと刀の型（スカートの物理あり）では、赤の出来事が全部一覧に出ていて、1件ずつ「直す」か「このままでよい」が決まっている。数は記録し、次の版で増えたら赤にする。
3. **体の点検**：体の穴が0、ひざの逆曲がりが0、足の床への沈みが0。足が届かないフレームは、全部一覧に出る。
4. **書き出し**（`convert_blend.py` の USDZ）：
   - いくつかの姿勢で、読み戻した形のずれが 0.5mm 未満。名前は対応表を通して比べる。
   - 1点に付く骨が4本まで。物理の部品が入っていない。衣装ごとの体の穴が0。
   - 補正の形が、7章1 で決めたとおりに扱われている。
   - 段階1を始める前の「基準」と比べて、意図しない変化が0。
5. **版の比べ**：「変えてよい所」の外の変化が0。再現性の幅より小さい差は、変化として数えない。
6. **ボタンだけで動く**：1〜5 がすべて、LLM と Jeff なしで、日本語のボタンだけで動く。

### 段階1.5　土台の残り（段階1のあと。段階2と並行してもよい）

- A2 目印さがし、A7 比べる画面と印つきの一覧画像、A12 日本語の手順の案内、A13 自動の点検。
  - 段階1は、道具ごとの日本語のボタンが並ぶ簡単なパネルにとどめます。A12 で、1画面ずつの案内にします。
- B1 取り込みの整え、B2 健康診断と修理、B3 骨とウェイトの点検と修理、B7 表情キーの点検、B8 表情の組み合わせの点検、B9 一体の服を部品に分ける、B10 小物の取り付け、B11 左右対称。
- M2 準標準の骨を足す（v065・v066 を汎用に）、M3 動きのお掃除、M7 揺れ物の点検、M8 足の IK（v068 を汎用にするだけ）、M9 モーションの編集。
- **M5 ぶつかる・届かないの自動直し**：測り方が本物の失敗で正しいと確かめてから作ります。
- E3 iPhone の重さの予算、E5 アプリでの見え方の確認（Blender と Mac の上で行う分）。

### 段階2　チャット（Jeff ＋ 27B）

- 必須：C5 AI の準備・メモリ・予定の係／C3 モデルのようすの要約／C1 Jeff の速い判断と引き継ぎ／C4 試しの頼みごと集／C2 チャットで頼む
- あると良い：C6 数字で形を直す／C7 計画を見せてから進める／C8 記録と手順の保存
- あとで：C9 画像での確かめ（C2 が動いてから、要るかどうかを決める）／C10 この道具用の Jeff の adapter（Jeff v1.3 がそろい、記録がたまってから）

**自動で行うこと**：見るだけの道具（要約・点検・撮影）は、すぐ動きます。

**ユーザーが確認すること**：形を変える道具は、写しで試した前後の数字と画像を見てから実行します。長い頼みは計画全体を1回承認し、消す操作だけは毎回あらためて確認します。

**できあがりの基準**（試しの頼みごと集は約300件で、書いた人の違うものを混ぜます。数字は目安で、変えられます）

- 道具の選び方の正解が 95% 以上、値が許す範囲に入るのが 90% 以上。
- 断るべき頼みは 100% 断る。断るかどうかは、目録にその道具が無いことで決まるようにします。あいまいな頼みで聞き返すのが 90% 以上。
- 形を変える操作が、確認なしに動いた回数が0。
- Jeff の「自信」と実際の正解率のずれが 5% 以内。この道具用の確かめの問題（英語の決まった文）を作ってから測ります。
- 速さの目安（届いた Mac mini で測って決め直します）：
  - ボタンと Jeff だけで済む頼みは数秒。
  - 27B を使う簡単な頼みは1〜2分。
  - 計画を立てる頼みは10分以内。
- チャットから操作したあとも、段階1の点検が同じ数字で通る。
- 採点にかかる時間：27B で300件を採点すると、1件1〜3分で合計5〜15時間かかります。数晩に分けて行います（5章の予定表）。Jeff の部分の採点はクラウドでもできます。

### 段階3　リギング

- 必須：R1 AI リギング／R2 体型が大きく違う服の付け替え。袖・ズボンのひじとひざの最小限の補正は R2 に含めます。
- あると良い：R3 関節の補正の形の自動作成／R4 揺れ物の自動設定／R5 表情の移植

**自動で行うこと**：関節の印の案、骨とウェイト、補正の形の案、点検。

**ユーザーが確認すること**：関節の印の位置（骨を作る前に必ず）、しわの好み、袖とすその長さの合わせ方（着せる体に合わせるか、デザインの割合を残すか）、写した表情の仕上げ、素材の利用条件（運ぶ前に表示します）。

**できあがりの基準**

- **R1**：骨を外した人型3体で試します。自動で置いた関節の印のずれは、その手足の長さの 5% 以内とします。ユーザーの手直しは1体あたり数か所までです。自動で付けた骨とウェイトで、段階1と同じ確かめが同じ基準で通ること。
- **R2**：体型の違う体へ両方向で試します。
  - 見える貫通の出来事が0。服と体のすき間が 1〜4mm。1点に付く骨が4本まで。
  - 袖やズボンのひじ・ひざが、曲げてもつぶれない。確かめの動きで合格する。

### 段階4　あとで（動き作りの上積み）

段階1が終われば、チャットやリギングとは別に進められます。対象は L3 ポーズ集と手の形、L6 動きのつなぎ目、L7 歩く・座る・横になる、L8 小道具を持たせる、です。

### 紅魔館（アプリ）の計画に回すもの

アプリのセリフは、LLM と音声合成（ポート 9880）がその場で作ります。そのため、次の物はアプリの中でその場で計算する方が合っています（紅魔館には待機の動きと LifeComponent がすでにあります）。Blender の道具からは外します。
- 口パク（前の L1）、セリフから表情と身ぶり（前の L2）、視線（前の L4）、待機の動き（前の L5）。
- アプリでの衣装の切り替え（E7）、焼いた動きの再生（E8）、アプリの中の点検画面（E5 の一部）、アプリで関節の補正を出すこと（7章の1）。

### 将来の候補（表から外したもの）

- 動画から動き（前の L9）、文章から動き（L10）、iPhone で表情を撮る（L11）、かんたんポーズ作り（L12）。32GB では重く、価値が出るのはほかの土台ができてからです。
- 表情の名前の対応（VRM・iPhone の顔、R7）。使う予定が決まってから作ります。
- 色と塗り方の変換（B15）、UV の引っ越し（B16）、ほかの形式の動き（M10）、アプリでのばねの骨（E9）。使う予定が決まるまで外します。
- glTF の書き出し。アプリ（RealityKit）は USDZ だけを読むので、確かめは USDZ だけにします。
- **外したもの**：目の組み立てキット（前の R6）。特定のモデル専用の作り方なので、汎用にする価値が小さいためです。
